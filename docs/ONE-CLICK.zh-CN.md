# 双击一键生成 iPhone 安装包或 Mac 应用

**完整下载并解压本项目，双击对应脚本，再按弹窗选择游戏目录、密钥文件和保存位置，脚本就会自动完成制作。正常使用不需要输入命令，也不需要编辑配置文件。**

## 开始前准备

- 一台 Apple 芯片 Mac，以及已安装、打开并完成许可确认的完整 Xcode。
- 自己的动森本体 NSP、**3.0.3 更新 NSP**和 `prod.keys`。本体和更新放在同一个文件夹，目录里只保留一个更新版本。
- 可用网络及至少 30 GB 可用空间，供依赖下载和制作过程使用。

要启用 Duo 专用适配，请使用 **Xcode 27.1 或更新 SDK**。其他可安装的构建依赖会由脚本自动检查、补齐。

## 选择要生成的内容

在解压后的项目根目录，双击下列脚本之一：

| 双击哪个脚本 | 适合什么情况 | 生成内容 |
| --- | --- | --- |
| `一键生成IPA和数据包.command` | 首次制作 iPhone 版，推荐使用 | 完整未签名 IPA、SHA256 校验文件，以及 `ACNHMobile` 数据文件夹 |
| `一键生成完整IPA.command` | 已经有可用的动森 `.data` 数据包 | 完整未签名 IPA 和 SHA256 校验文件，继续配合原有数据包使用 |
| `一键生成Mac应用.command` | 在 Mac 上直接游玩 | 可双击运行的 `ACNH Mobile.app`，包含所需游戏资源和 Mac 着色器 |

**需要整个项目源码，不能只下载一个 `.command` 文件。** 项目外层文件夹可以改名或换位置，但请保持内部目录结构完整。

## 双击后怎么选

每次双击都会依次弹出三个独立的选择窗口。顶部步骤提示、说明与确认按钮会跟随 Mac 系统语言，支持简体中文、繁体中文、日文和英文，其他语言使用英文。窗口顶部显示步骤编号与当前要选择的内容，不再额外显示底部重复提示；密钥窗口只允许选择名为 `prod.keys` 的文件：

1. **选择游戏目录**：顶部提示注明“仅支持游戏 3.0.3”。选中同时放有动森本体和 3.0.3 更新 NSP 的文件夹，其他更新版本无法构建。这里的 3.0.3 指游戏版本，并非应用自身的 0.3.x 版本号。
2. **选择密钥文件**：选中自己的 `prod.keys` 文件。
3. **选择保存位置**：选中希望放置成品的文件夹，也可以在这个窗口新建文件夹。

选完后，脚本自动检查和补齐依赖、提取游戏、校验版本、改写程序、转换配套 Metal 着色器，最后编译并校验成品。终端会显示进度；请保持窗口开启，等待出现“完成”和成品路径。

动森地图透明度补丁已随源码配置，一键制作会自动带入，不需要另行复制补丁或修改代码。补丁或源码变化会影响缓存校验，不能把旧着色器目录改名后冒充新缓存。补丁说明见 [动森专属地图补丁](../dm/games/01006F8002326000/MAP-FIX.zh-CN.md)。

每次双击都会重新选择，不会直接沿用配置中的旧游戏、密钥或输出位置。中途取消选择不会开始制作。第一次处理可能较慢。

## 到哪里找成品

**成品就在第三步选择的保存文件夹中。** 支持选择另一块磁盘：脚本会复制并校验数据包和 IPA，确认完整后再完成输出。

例如选择“一键生成 IPA 和数据包”，会得到：

```text
你选择的保存文件夹/
├── ACNHMobile-v版本号-build构建号-unsigned.ipa
├── 同名.ipa.sha256
└── ACNHMobile/
    ├── ACNH-index.data
    ├── ACNH-001.data
    └── 其他 .data 分卷
```

iPhone 的 IPA 需要自行整包签名、安装，再将数据文件夹放到应用的 `Documents/ACNHMobile`，或启动时选择对应的数据文件夹。`.data` 会直接读取，手机无需解压；已有完整、可用的数据包可以继续使用。

选择 Mac 入口则生成 `ACNH Mobile.app`，双击即可启动，不需要另外配合 iOS 的 `.data`。系统要求、按键和存档位置见 [Mac 应用制作说明](MAC-APP.zh-CN.md)。

## 自动安装依赖与清理缓存

每次运行仍会自动检测依赖，缺少时安装可安装的构建工具及 Python 依赖，无需逐项确认。完整 Xcode 及许可需用户先完成；依赖安装若遇到网络或权限问题，终端会显示原因。

**成品全部生成、校验成功后，自动清理本次编译、提取、程序改写和着色器转换缓存。** 保留成品、日志、原始游戏、keys 和已安装依赖；失败时保留现场，便于重试和排查。下次制作会重新准备缓存，因此仍需要一定时间。

终端会显示构建日志路径。成功后，输出目录最多保留最新与一个旧 IPA，同版本重复包移入废纸篓；游戏数据包和存档不会清理。

脚本使用用户自己的游戏及密钥，不自动下载或上传这些文件，也不会自动推送、发布、签名或安装生成的完整包。

<details>
<summary>进阶：命令行与已有预处理输入（普通双击使用无需设置）</summary>

命令行用户可直接指定三个路径：

```sh
./一键生成IPA和数据包.command \
  --game-dir '/path/to/game' \
  --keys '/path/to/prod.keys' \
  --output-dir '/path/to/output'
```

Mac 入口同样支持上述参数。使用 `--select` 可主动打开选择窗口；直接双击已经会自动打开，无需额外操作。

需要复用手工准备好的程序和着色器时，可将 `config/local-build.example.json` 复制成根目录的 `local-build.local.json`，配置 `data_root`、`patched`、`romfs`、`shaders`、`font` 等路径，再从终端运行对应入口并传入参数，例如 `--config ./local-build.local.json`。这类手工输入不会在成功后删除。Mac 构建需要配套的 Mac 着色器，不能使用 iOS 着色器。

`output_root`、`work_root` 可设置非交互模式的输出目录和私人工作目录，默认是项目中的 `outputs/`、`work/local-build/`。交互选择的保存位置优先于 `output_root`。工作目录不要放在原始游戏目录内。私人配置不提交到 GitHub。

只检查输入和依赖、不安装或构建时，可运行：

```sh
./一键生成IPA和数据包.command --plan \
  --game-dir '/path/to/game' \
  --keys '/path/to/prod.keys' \
  --output-dir '/path/to/output'
```

原有 `./setup.sh build --patched … --romfs … --shaders … --font … --work … --output …` 接口保持不变。

### 首次启动工具检查

从原始游戏构建时，脚本会先编译并试运行 `dmsh_xlate --source-sha`，通过后才开始提取游戏和生成着色器。如果被 macOS 拦截，终端会在此暂停：确认工具来源后，由用户在“系统设置 → 隐私与安全性”中选择“仍要打开”，再回到终端按回车重新检查并继续。脚本不会更改系统安全策略或自动移除隔离标记。

放行仅针对当前工具；重新下载项目或重新生成工具后，系统可能要求再次确认。若检查失败但没有系统拦截提示，请查看终端给出的 `translator-preflight.log`，其中也可能是运行环境错误。
